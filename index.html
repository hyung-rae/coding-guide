웹 서비스 지도

블록을 누르면 해당 설명으로 이동.

⇄ ⇄
1🖥️

프론트엔드 Frontend

“눈에 보이는 집의 외관과 인테리어”

사용자가 브라우저에서 보는 화면 전체.

  • HTML 뼈대. 제목·입력창·버튼의 위치와 구조
  • CSS 스타일. 색상·크기·배치·글꼴
  • JS 동작. 버튼 클릭 시 모달 열기 등
2🧩

프레임워크 Framework

“벽돌을 쌓는 대신 규격 모듈을 조립해 짓는 집”

  • React 화면을 부품(컴포넌트) 단위로 만들어 조립하는 도구
  • Next.js React 기반 프레임워크. 화면과 간단한 서버 기능을 한 프로젝트에서 개발 가능
  • “Next.js로 만들어줘” 요청 시 표준 구조로 코드 생성
3⚙️

백엔드 Backend

“집 뒤편의 전기·수도 관리실과 경비실”

눈에 보이지 않는 서비스의 뒷단 로직.

  • 서버 사용자 요청을 받아 처리하는, 항상 켜져 있는 컴퓨터
  • 역할 로그인 검증, 결제 처리, 데이터 요청 처리 등
4🗄️

데이터베이스 DB

“잠겨 있는 서류 보관함과 장부”

데이터를 영구 저장하는 곳. 서버가 꺼져도 데이터 유지.

  • 회원 정보, 게시글·댓글, 결제 내역 등
비밀번호는 원문 저장 금지 되돌릴 수 없는 값(해시)으로 변환해 저장. 로그인은 직접 구현보다 Supabase Auth 같은 인증 서비스 사용 권장.
5🌍

배포 Deployment

“집에 주소를 붙이고 누구나 찾아올 수 있게 공개”

내 컴퓨터(로컬)에서 만든 서비스는 나만 접속 가능 → 인터넷에 올려야 공개됨.

  • Vercel Next.js 앱(화면 + 서버 기능)을 인터넷에 올려 주는 서비스
  • Supabase DB와 로그인 기능을 제공하는 서비스
  • 도메인 my-service.com 같은 인터넷 주소
💡

데이터 흐름 로그인 예시

‘다음’ 또는 ‘자동 재생’으로 요청이 오가는 순서 확인.

🖥️프론트엔드
⚙️서버
🗄️DB
  1. 프론트엔드 로그인 버튼 클릭
  2. 서버 요청 수신 → DB에 사용자 정보 조회
  3. DB 사용자 정보를 서버로 전달
  4. 서버 입력한 비밀번호와 비교 → 결과를 프론트엔드로 전달
  5. 프론트엔드 마이페이지로 전환

꼭 지킬 안전장치

①🔑

API 키는 .env 파일에만 보관

  • API 키 외부 서비스 이용용 비밀번호. 유출 시 요금 도용·데이터 노출 위험
  • 코드에 직접 쓰지 말고 .env.local 파일에 보관
  • .env 파일은 GitHub 업로드 금지
  • 배포 시 Vercel의 Environment Variables에 별도 입력
API 키는 환경변수로 빼줘
